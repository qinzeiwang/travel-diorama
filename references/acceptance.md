# 对照验收：先对应，后漂亮

## 验收证据

同时查看原照片和实际成图。只看提示词、文件名或程序输出不能进行视觉验收。样图得到用户方向认可，与每个物体逐项无误不是同一件事。

每项用 pass / fail / unchecked 记录，并写一句可观察依据。不使用未经验证的相似度分数，不以颜色直方图或像素相似度替代空间关系检查。

## 七项门槛

| 项目 | 通过条件 | 失败示例 |
| --- | --- | --- |
| source_match | 场景类型、主景、山脊轮廓和整体动线对应原图 | 林荫路变海湾；道路弯向反转 |
| anchors_and_relations | 必保景物可辨，位置、相邻和遮挡关系对应 | 护栏与步道交换；建筑移到另一侧 |
| people | 原图有则卡通化且关系对应；没有就不加 | 新增游客；人数改变；远景人物放大；人物仍像写实照片 |
| container_integrity | 结构、支承与边界成立 | 穿壁；瓶盖穿树；箱子漏水 |
| three_dimensionality | 薄地形边缘及独立体积可辨，玻璃容器有空隙，上盖浮雕有厚度或层间阴影 | 整张照片贴在瓶内或上盖 |
| color_and_materials | 颜色干净鲜活，中性物体不偏色，材质有区别 | 荧光绿；过曝；统一塑料亮面；雾景被锐化成清晰山峦 |
| no_extras | 不含原图无依据的突出物件或额外文字 | 猫、船、花墙、纪念文案 |

逐一对必保锚点留下检查记录。非关键远景细节可简化，但不能使照片的整体组织方式变形。

## 处理顺序

内容或结构失败，先修复这些错误；不要先提升饱和度。调整提示词时指出具体偏差，例如“白栏杆必须在道路右侧，彩色步道在栏杆外侧”，不要只写“更像原图”。

实际工具支持编辑时，优先修正局部；仍然提供原照片。无法查看成图时保持 unchecked，不宣称验收通过。

## 脚本的边界

`check-review` 只验证文件哈希、填写人标记、完整的七项记录和必保锚点记录。它不会独立识别人物或景观，不会通过图像相似度作决定。记录中的 pass 来自真正看图的人或视觉模型。

## 已验证范围

已尝试道路、人物、雾景与雪景。远山层次、雾感、云团及人物比例仍可能偏离，需要逐图复核；示例不代表稳定成功率。夜景与雨景未测。
